# Saves, Character Files, and settings

Adventure saves, Character Files, and presentation settings are three separate repositories. Saves atomically preserve the complete session aggregate. Character Files store immutable character revisions and import detached copies. Settings store host presentation choices and never enter gameplay state.

Saves write v7 and read v5-v7. V7 carries VM snapshot schema 4 with type-tagged Safe Action values (ADR 0026) and the per-run step-budget facts (ADR 0027). Both readable save versions and Character Files v2 require each character's exact equipped-instance order so cap- and floor-sensitive equipment effects restore deterministically. Save v1–v4 and Character Files v1 are incompatible; browsing reports them without migration, overwrite, or deletion.

Each repository validates untrusted input before replacement and uses a temporary write, readback, backup, and same-volume rename where applicable. Start in the corresponding repository under `src/storage`; use the save and character-vault suites for transactional evidence. Never solve a migration by weakening package, identity, or path validation.

Character Files presentation is owned by `src/ui/characters/vault_screen.tscn`. Its library, detail, empty, and inspection regions are editor-authored; `VaultScreenBinder` and `VaultDetailBinder` bind immutable revision views into the exported row and revision-row scenes and emit archive, restore and delete requests that the host applies to the repository. Permanent deletion is offered only for archived characters, after a confirmation that defaults to Cancel; the repository also refuses a character that still has a current revision index or any file it can't read (the vault's own `.bak` rotation backups are accepted), and a party member can be neither archived nor deleted. A deleted character's identity is retired in a crash-safe ledger, so a new character never reuses it; if that ledger becomes unreadable, deletion and character creation stop with a reason instead. Restoring an archived character defaults to the revision it was archived from (shown as Last active). Once starters have been offered, deleting every character never reseeds them; Restore starter characters stays explicit.

Save & Load presentation lives in `src/ui/shell/save_load_screen.tscn` and the shared `system_workspace.tscn`. Edit the ten named `SavePreview_A_primary` through `SavePreview_J_primary` buttons in that workspace. They retain identity during refresh; `SystemScreenController` binds detached previews and inserts only variable backup and earlier-save rows, with each backup beside its primary. Selection, confirmation, and host requests remain separate from repository mutation.
