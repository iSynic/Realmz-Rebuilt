## Local Contracts

- The startup probe records initial focus, activates Choose a Scenario with viewport joypad press/release events, and fails unless scenario selection becomes visible. Its isolated window tests native delivery through Godot; it does not prove physical device comfort or mapping.

- Maximum-frame diagnostics retain the matching sample's detached coordinate, clock, fatigue, change domains and event kinds after its timing boundary; they must not mutate gameplay or alter performance budgets.
- The rendered movement probe's optional sixth `movement-frames` argument requests an exact positive sample count within the existing duration ceiling; ending early fails. Before/after comparisons match that count, route, ordinary/hourly populations and initial/final canonical save hashes. Save hashing occurs after measurement and never changes cadence or the absolute gates.
- Tools must resolve the repository root from their own path and avoid machine-specific committed paths.
- Native release settings default to Godot's Mobile RenderingDevice path. `verify_export_contract.ps1` preserves that default, while Compatibility/OpenGL remains a documented command-line override rather than a separate simulation or package variant.
- `verify_export_contract.ps1` invokes the application-icon verifier so the Godot project icon, native Windows/macOS icon paths, source provenance, reviewed PNG hashes, and exact ICO/ICNS payloads cannot drift independently.
- Do not modify source-reference worktrees or commercial campaign installations.
- Keep local absolute MCP/server configuration untracked.
- The vendored MCP plugin must skip initialization in headless editor processes so verification cannot claim or remove a live interactive editor's temporary runtime-service autoloads.
- The aggregate headless test gate captures process output and fails on ObjectDB leak or retained-resource teardown diagnostics, even when Godot exits zero.
- Keep the universal macOS export preset on ETC2/ASTC texture import; `verify_export_contract.ps1` enforces the exporter requirement.
- `verify_release_artifact.ps1` validates one completed export inventory, strips terminal color escapes before matching export-log inventory, rejects development or unexpected package resources, requires the application library plus the exact provenance-pinned 13-scenario bundle and platform PCK, verifies the Windows executable's 32-pixel icon and the macOS bundle's exact ICNS bytes, and writes an ignored per-platform artifact/package/icon hash manifest. It never names or ships the synthetic test fixture. `verify_export_contract.ps1` also rejects tracked MCP runtime autoloads whose scripts are intentionally absent from releases. Native CI launches each exported runtime before uploading the complete platform directory.
- `convert_classic_starter_characters.py` accepts only the exact six 872-byte Realmz 7.1.2 files and pinned application-library package, then deterministically emits the trusted starter catalog; raw fixtures remain public engineering inputs under `tools/fixtures` and never enter exports.
- `public-source-manifest.json` plus `create_public_staging.ps1` build a no-history staging tree from an explicit allowlist. Staging requires a clean tracked source/index and copies committed files only; untracked local overlays are never public inputs. They omit the local Godot MCP editor addon and private migration records, and write public project settings with only the Realmz Builder editor plugin enabled. `verify_public_source.ps1` rejects internal/generated paths, local paths, local editor tooling, non-LFS packages, invalid ZIP packages, and oversized Git blobs in the sanitized repository.
- `sync_public_staging.ps1` updates an existing clean public checkout from that same manifest after the first release. It requires a named review branch, never writes `main`, preserves `.git`, copies committed public inputs, and removes only destination-tracked paths that are no longer public inputs.
- Sanitized public history retains source-backed workflow evidence but cannot contain its private preparation baseline object. `verify_application_workflow_inventory.ps1` skips only that ancestry lookup when `.realmz2` packages use the public Git LFS boundary; the internal binary-package history continues to require the baseline commit as an ancestor.
- Public CI uses shallow LFS checkouts on Windows, Linux, and macOS, runs verification, exports and launches each native runtime, and retains export/smoke logs with the manifest. The tag workflow rebuilds the exact `v*` commit, packages all three platforms, generates `SHA256SUMS`, and creates only a draft prerelease for owner review.
- Chickensoft's Windows setup exposes Godot through an extensionless hardlink. Verification and export workflows copy that exact executable to a temporary `.exe` path before invoking Windows gates; Linux and macOS execute the supplied path directly. Apply the same resolution in main and tagged-release workflows.
- Architecture verification resolves repository-relative paths with the host directory separator, enforces platform-appropriate path comparison, and slash-normalizes results before applying dependency rules.
- The aggregate verifier forwards its resolved Godot executable to nested engine-backed gates; nested checks may not rediscover a platform-specific installation independently.
- Native export jobs use the shared streaming-process boundary so GUI-subsystem Windows executables are awaited with a trustworthy exit code. Native startup logs use absolute paths and are required artifacts before content inspection.
- Windows native-smoke invocations quote the absolute `--log-file` value inside the single `Start-Process` argument string; array arguments are forbidden there because PowerShell rejoins them without preserving a path containing spaces.
- An action-list route step may execute its named compiled XAP/ED3 program directly when the record has no map topology. Reports must keep that distinction from placed AP reachability.
- Tier 2 report regeneration is allowed only when the authoritative workflow inventory changed; never use `-Write` for an unrelated workflow edit and never hand-edit the generated status report.
- Tier 2 scope checks permit only synthetic test packages, the exact committed application Character Files catalog, and the provenance-catalogued Castle-distributed campaign directory. Every other `.realmz2` remains a local/install artifact and fails the workflow gate.
- Tier 3 runs `verify.ps1` once per workflow batch, plus clean-reference evidence validation, relevant Providence full checks, and one coherent MCP walkthrough.

## Work Guidance

- PowerShell is the primary Windows automation surface. Fail immediately on command errors.
- PowerShell scripts must parse under Windows PowerShell 5.1 from UTF-8-without-BOM checkouts; keep generated Markdown literals ASCII-safe unless the script explicitly reads or writes UTF-8 with a declared encoding.
- Every meaningful tool change receives the applicable DOX pass: re-read the nearest `AGENTS.md`, check the allowed scope, preserve repository-relative paths, and report the exact focused or batch-level evidence used.
