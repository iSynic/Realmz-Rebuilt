# Authoritative topology evidence

This document records the evidence boundary for the Phase 2 world model. Providence compiles legacy/native representation details into explicit runtime topology. `MapTopology` plus session-owned `WorldState` overlays then answers every gameplay query; `GameView` is the presentation-safe projection of those answers.

## Castle source/control-flow evidence

Evidence label: `source-control-flow` at Castle commit `491816ad60037394f92c428e99c004494d3c28b3`.

- `src/realmz_orig/threed.c:515-550` reads the destination dungeon field before committing movement. A directional bit matching `8 - head` permits forward entry and records discovery; another directional-secret mask blocks entry; note/encounter markers and a non-wall field permit entry; door bits are observed after the move. This proves that wall, door, directional-secret, and encounter facts belong to the destination-cell movement decision.
- `src/realmz_orig/checkforsecret.c:38-72` searches the surrounding 3×3 area. Land secrets use the encoded terrain band, while dungeon secrets use mask `3840`, skip already revealed bit 9, roll `Rand(100)`, and set reveal/arch bits on success. This proves that search mutates playthrough state over otherwise immutable map facts.
- `src/realmz_orig/buttonchoice.c:75-96,107-146,153-205` strips the undiscovered-land-secret 3000 band before consulting the underlying tile's movement facts, so a passable land cell remains enterable before discovery. That normalization also keeps a concealed colocated AP below the door/AP band; after `checkforsecret.c` removes one 1000 band, the same cell enters the door/AP branch and calls `newland`. Discovery therefore activates the marker and colocated trigger without changing terrain collision. Directional dungeon secrets retain the separate edge behavior above.
- `src/realmz_orig/cansee.c:41-152` evaluates a blocking tile and then marks that tile in `site` before stopping the current sweep. This proves the first wall or other LOS-blocking cell remains visible while cells beyond it stay hidden; Wizard's Eye skips the blocker stop without changing the bounded sweep.
- `src/realmz_orig/centerpict.c:74-186` renders a 15×13 land window in 32-pixel cells. It selects a one-based tile from a 20-column atlas with `top = (tile - 1) / 20 * 32` and `left = (tile - 1) % 20 * 32`; `fastplot.c:14-35` uses the same addressing. This proves the normal land presenter should use the decoded atlas at native 32×32 size rather than scale each cell to 48 pixels.
- `src/realmz_orig/buttonchoice.c:47-74` changes the persistent land-facing flag only when horizontal movement is requested: west selects `face = 0`, east selects `face = 1`, and north/south preserve the previous facing. `src/realmz_orig/centerpict.c:198-238` places a 32×32 CICN over the party's land cell and selects built-in CICN `175 + 11 * face`, yielding exact left-facing CICN 175 or right-facing CICN 186; notes, boats, camp, and base-scale tactical states select different resources. Realmz Rebuilt uses both exact assets from `The Family Jewels.rsrc`. A scenario-local resource may reuse either numeric ID for unrelated art, so provenance includes the owning resource fork rather than the ID alone.
- `src/realmz_orig/checkkeypad.c:126-145` assigns both `deltax` and `deltay` for keypad 7, 9, 1, and 3. `buttonchoice.c:48-58` independently derives both axes from the mouse position around the party cell, and `buttonchoice.c:75` queries that single diagonal destination tile. `checkkeypad.c:4-54` applies both nonzero deltas while locating an adjacent Layout cell, and lines 289-327 wrap both coordinates when that diagonal move crosses a map corner. Realmz 2 therefore permits eight-direction land travel and diagonal Layout transitions while retaining cardinal edge traversal in dungeons.
- `src/realmz_orig/buttonchoice.c:153-218` preserves all three `needboad` meanings rather than reducing them to a boolean. Out of a boat, value 1 asks question 15 and an accepted answer moves the party before replacing the boat cell with active-landlook tile 60; value 2 blocks ordinary travel. In a boat, only value 2 is traversable. Solid or shore terrain first plays sound -148; a shore increments `hitland`, asks question 14 on the third attempt, and an accepted answer leaves the boat on the party's current cell as tile 147. Every branch then applies the attempted tile's map sound and time, while a nonpositive raw cell uses sound 82 and three timeclicks. `save-direction-order.c:409` and `loadsavedgame.c:345` persist `inboat`; `hitland` is a transient global with no save-field write.

- `src/realmz_orig/textbox-time.c:376-426` visits matching random rectangles from slot 19 down to 0, rolls `Rand(10000)`, consumes three ordered random-door rolls, clears a positive door percentage after success, optionally asks the player whether to take a favorable surprise, rolls a separate 10-percent unfavorable surprise, and then selects the battle. The 2.0 session preserves that order and serializes both one-shot door state and the surprise interaction.
- `src/realmz_orig/newland.c:70-91` scans placed AP slots 0 through 99, copies the first matching coordinate record, and leaves the scan before checking its percentage. A selected percentage below one returns without drawing; a positive sub-100 percentage draws once and returns on failure. Neither path resumes the slot scan, so a later same-cell record cannot fire.
- `src/realmz_orig/structs.h:49-56` stores `landid`, `landx`, and `landy` in each `door`/AP record. `newland.c:3742-3772` applies those fields after the action sequence as a level and position destination, then allows one `seconddoor` recheck. `flashrange-loaddoor.c:43-59` preserves the current AP's destination fields while loading XAP code. This proves the AP header is post-action location data, not terrain replacement data, and that macro transfer must retain AP origin context.
- `src/realmz_orig/buttonchoice.c` strips the hidden-secret `3000` band before testing the underlying terrain's independent `Data Solids` entry, so concealed secrets preserve authored collision. Action-point and revealed-secret marker bands route through the door/action-point branch and call `moveparty(1)`, making a discovered entrance enterable even when its underlying terrain is solid. Unmarked negative special land still uses its base terrain for traversal, its independent solid bit, sound 82, and three timeclicks.
- `src/realmz_orig/newland.c:2336-2350` identifies opcode 24 as Keep Codes and opcode 25 as removal of the retained door/AP location; `flashrange-loaddoor.c:43-59` preserves that location when XAP code is loaded. At `newland.c:3729-3730`, a completed placed AP otherwise sets its saved percent to `-1`. Realmz 2 therefore disables an ordinary AP only after its full direct or resumed timeline succeeds, preserves it when opcode 24 is reached, and lets a source-less XAP end without inventing Castle-visible missing-origin failure text. This corrects replaying story APs such as Assault's starting AP without coordinate- or campaign-specific exceptions.
- `src/realmz_orig/threed.c:493-556` settles the packed dungeon movement exceptions. Wall bit `0x0001` blocks without time unless a door (`0x0002` or `0x0004`), note (`0x0020`), AP marker (`0x1000`), or direction-matching secret (`0x0100`, `0x0200`, `0x0400`, or `0x0800`) permits the step. A nonmatching secret and visible arch `0x2000` alone remain blocked; a traversed secret is revealed.

These observations do not prove final 2.0 search chances, every diagonal LOS edge case, or presentation timing. Timed-encounter coordinate behavior is separately recorded under `FD-EXPLORATION-001`: Castle's retained movement delta and mistyped y guard are observed source behavior, while Realmz Rebuilt uses the semantic attempted/current/committed coordinate.

## Providence compiler normalization

Providence commit `efee09f5ce05de7000dacf20efb0ebbc72bcd047` is the current authoritative compiler checkpoint. Its inherited `src-tauri/src/dungeon.rs` decoder names packed dungeon bits, and the `.realmz2` exporter converts those bits into stable cells, directional edges, and explicit features. Providence compiles all eight neighboring Layout cells into explicit bidirectional map transitions, orders same-cell placed AP references by native record index, retains AP headers as validated post-action destinations, and preserves complete race aging tables. Classic land matrices use their native `x * height + y` storage while dungeon matrices remain `y * width + x`; both compile to explicit `(x,y)` cells. Topology-v2 additionally compiles exact `needboad`, blocked-attempt timeclicks, the source-backed forest semantic and special dungeon passability matrix, each map's exact nullable base scale, and each active-landlook's tile-60/tile-147 replacement profiles. Referenced land atlases, negative-land `cicn` overlays, the normalized PICT 302 dungeon-composition atlas, and the complete PICT 302 battle atlas become immutable package media, while packed native values do not enter the runtime package as an alternate topology. Reachable battles additionally require complete active-landlook and global combat mapstats catalogs; these source-backed 3×3 build and solid facts are immutable battle-construction inputs and do not compete with `MapTopology` for exploration truth.

The runtime mirror is schema v3 at SHA-256 `12376856235a11f507b993835acad87b546f87b9ad519533967ed2701ddb89cd`, mirrored from Providence commit `efee09f5ce05de7000dacf20efb0ebbc72bcd047`. ## Realmz 2.0 behavior and proof

Target behavior:

- `MapTopology.probe_entry` owns passability, wall, door, and secret entry decisions.
- `MapTopology.probe_movement` owns the target-cell-only land step, including diagonal destination terrain and the underlying passability of undiscovered-secret cells, while preserving cardinal dungeon secret edges. Post-move trigger selection independently suppresses a colocated land AP until that secret's discovery overlay is set. `WorldDefinition.probe_movement` adds the compiled Layout boundary without duplicating passability.
- `MapTopology.find_path` uses eight land probes or four dungeon probes from that same movement query. LOS, visibility, movement, search, trigger discovery, random-region membership, and presentation views consume the same cells, edges, features, and overlays.
- `FD-TOPOLOGY-001` is a deliberate player-visible correction to Castle's unchanged Wizard's Eye sweep. Ordinary LOS retains the radius-eight supercover probe, while an active Wizard's Eye both bypasses occluders and doubles the authoritative exploration radius to sixteen. The result remains map-bounded, deterministic, presentation-independent, and is recorded into the same exact per-map sight memory as ordinary visibility.
- `WorldState` owns terrain replacements, exact boat-presence overlays, opened doors, discovered secrets, disabled triggers, and visited/minimap cells in the save aggregate. `MapTopology.effective_cell_at` projects an ordinary positive terrain replacement through the active landlook's immutable mapstats profile, then applies the compiler-owned tile-60/tile-147 boat profile before any movement, LOS, presentation, or battlefield consumer reads the cell. Signed special-land and positive CICN overlays retain their separately compiled base-cell semantics because their independent `Data Solids` facts are not mapstats records.
- Boarding, declined boarding, water traversal, shore collision, third-attempt disembarkation, and declined disembarkation use one typed movement workflow. The `boat-choice` continuation re-probes immutable content and mutable overlays on response and restore. Realmz Rebuilt deliberately persists the bounded zero-through-two shore retry cursor even though Castle does not save `hitland`; otherwise saving at a committed prompt boundary could alter which attempt asks the player.
- Battle setup derives one serializable 90×90 `BattlefieldState` from the current authoritative map, live terrain overlay, and immutable battle-terrain catalog. Its terrain, source shift, party anchor, actor positions, and complete footprints are session state; `BattlefieldView` is a detached projection. Presentation caches may render that result but may not answer tactical occupancy or terrain questions independently.
- Placed APs are one-shot by default after successful completion. Opcode 24 Keep Codes is the source-backed repeatable exception, while opcode 25 explicitly removes the issuing AP.
- The post-move continuation owns only the lowest-record placed AP selected for that coordinate. Inactive, world-disabled, percent-zero, and failed-chance paths proceed to random rectangles without examining later same-cell APs.
- `ClassicMapPresenter` consumes only `GameView`; its clipped, party-centered native 32-pixel atlas view, preserved native-size mounted party CICN, minimap, and opt-in debug facts cannot become simulation authority. It does not draw directional arrows around the party image. The geometric party ring is a missing-asset fallback only. Normal play does not draw fabricated land-edge walls, AP diamonds, random-region boxes, or cell grids over Classic art.
- `GameView` projects at most a 25×25 party-local cell window while carrying the complete visited-coordinate set and eight land or four dungeon topology-probed movement answers. This reduces presentation work without creating an alternate map or passability model.
