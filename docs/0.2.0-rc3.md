# Realmz Rebuilt 0.2 Release Candidate 3

Release Candidate 3 fixes scenario allies who couldn't die in battle. Everything else is the same as Release Candidate 2, including the missile-mode attack fix, the new scenario runner and save v9.

[Downloads for Windows, Linux, and macOS](https://github.com/iSynic/Realmz-Rebuilt/releases). Choose Release Candidate 3 explicitly, extract the complete archive, and keep its importer and music-importer folders with the game. This is an opt-in prerelease with desktop builds only; no Android APK is included. **Beta 27 remains the Latest release and the fallback.**

## Combat fix

- **Revived scenario allies sit out the rest of the battle** ([#26](https://github.com/iSynic/Realmz-Rebuilt/issues/26)). Some scenario NPCs, such as Jhalor Fireblade and Naryl Dragonstone in Trouble in the Sword Lands, use code 119 so they survive the story. Previously they got straight back up at 1 Stamina and kept fighting, so they could never be killed. Now, as in the Realmz Castle codebase, a killed NPC leaves the battlefield and takes no further turns, then rejoins your party with 1 Stamina once the battle ends.
- We checked this against the Realmz Castle codebase by playing the same test battle in both games: the revived ally sat out every remaining round in each.

## Saves and returning to earlier versions

**Release Candidate 3 writes save v9 and reads v5–v9. Beta 27 cannot read v9.** Keep an untouched v8-or-earlier save if you want to return to Beta 27. All versions use the same local data folder, so back up saves and characters you care about before testing.

A battle saved while a revived ally is sitting out records that fact. Release Candidates 1 and 2 refuse that save instead of misreading it; finish the battle first if you need to go back to an earlier release candidate. Other saves are unchanged.

Character Files, the application library, the bundled scenario archives and the package formats are unchanged. No reimport or Update Save step is needed.

## What to test and report

Please keep testing the new scenario runner as described in the [Release Candidate 1 notes](beta-28.md): encounters, scripted battles, death and revival, timed events, and saving and restoring while a prompt is open. For this fix, let a scenario NPC fall in battle and check that it stays out of the fight, then rejoins you afterward.

Use the [beta bug report form](https://github.com/iSynic/Realmz-Rebuilt/issues/new?template=beta_bug.yml). Include the version, operating system, scenario, exact steps, and an original save from before the problem when possible. Check attachments for private information before sharing them.

## Known limitations

The intermittent combat spellbook-input issue remains unresolved: Power Level, Choose Targets, and Abort can sometimes stop responding while Back to battle still works. Returning to battle and reopening Spells may help.

The optional modular HUD remains a work in progress; the fixed HUD is still the default. Verification covers the documented execution, restoration, legacy-save, campaign-caller and combat cases. It does not certify every route through every campaign.
