# Godot presentation contract

## Purpose

Own scenes, controls, screen presenters, topology-derived rendering caches, animation, audio, and accessibility settings.

## Ownership

- Classic-wide 2D shell and optional topology-derived 3D dungeon presenter.
- Translation of user input to typed intents/responses.
- `InteractionPresenter` is the dedicated Classic interaction layer. It owns modal/request identity and delegates text/choice, selection, encounter, shop, temple, bank, battle, and one-item recovery controls to typed components that emit `InteractionResponse.Body` variants. Combat targeting and presentation-only commands use explicit typed signals rather than a dictionary command bus.
- Consumption of `GameView`, domain events, and interaction requests.
- `ClassicMapPresenter` rendering of one explicitly framed map stage, optional traveled-area preview, and debug facts from detached map/cell views. It does not expose redundant map-level or input-tutorial headings.
- Consumption of detached app-owned view models, including `CharacterVaultRevisionView` from `src/app/view`; presentation does not define, duplicate, or compatibility-wrap those views and does not consume infrastructure records directly.
- `ClassicBattlefieldPresenter` rendering of the actor-centered native tactical viewport from detached battlefield facts and validated package media.
- `DungeonGeometryProjection` and `DungeonMap3DPresenter` derive floor, wall, door, secret, stair, and column geometry from the same detached topology view as 2D.
- `ClassicAudioPresenter` owns playback from the composed Classic media catalog. `ApplicationMediaCatalog` owns versioned built-in media, and `ClassicMediaCatalog` resolves an exact scenario-package override before the application fallback. Both consume the core `MediaSource`/`MediaAsset` contracts and never depend on package repository or archive classes.
- Picture and sound presenters resolve exact Classic resource type/ID pairs and expose developer-only resolution diagnostics with the owning catalog, asset, hash, and decoder outcome. They never search by numeric ID alone.
- `ClassicApplicationShell` is the sole scene-backed application composition. It owns the compact menu, framed map/picture stage boundary, separately framed right roster, bottom narrative/status well, and contextual command deck. Scenario media diagnostics remain developer-only; the visible picture stage never prints package-internal asset IDs. `ClassicScreenRouter` owns route registration, primary-workspace replacement, history, and focus restoration; route-local controllers own workspace construction and local selection/settings state. Neither boundary may mutate `GameSession`.
- The exploration footer spans the full shell as three aligned regions: an expandable Adventure command pane, the fixed-measure narrative/status well, and an expandable Party command pane. Search mode, held Area Search, Torch, Camp, Rest, the single contextual Shop/Temple/Encounter slot, and Preferences belong to Adventure; Money, Items, Spells, and Maps belong to Party. Extra widescreen room grows the command panes rather than the narrative line length. Typed light state remains visible beside location, fatigue, time, and wealth. Camping changes only the Adventure pane to a labelled inset state and replaces Camp with an explicit text-backed Leave Camp action. Do not expose a generic Service command or Castle's hardcoded developer Speak vocabulary in release UI.
- `UiRouteCatalog` is the single route, label, shortcut, and workspace-scene registry. `ClassicCommandCatalog` is the single command/asset/action/context/availability/focus registry. `UiLayoutProfile` owns only the optional 800x600 Compact and canonical 1280x720 Wide compositions after interface density is applied.
