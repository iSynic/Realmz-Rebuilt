# Realmz 2 Classic-wide interface strategy

Realmz 2 uses one responsive visual language whose play composition is recognizably Classic Realmz: a dominant map or picture stage, a scene-authored six-character roster on the right, a narrative/status well along the bottom, a contextual command deck, and a compact Pause menu. Character, Inventory, Spells, Services, Maps, and System are full-width application workspaces with their own task-specific selectors; they do not reserve an empty play roster. The application does not use a dashboard title bar, generic card grid, or permanent Chronicle inspector.

The complete visual denominator and remediation decisions live in `docs/ui-visual-audit.md`. Its Pen boards are composition contracts for screen families; this document remains authoritative for runtime ownership, fidelity, accessibility, and responsive behavior.

Other window sizes may use the nearest responsive fallback, but they do not create additional layout requirements or independent Pen designs. ## Input, focus, and interaction

- Mouse, keyboard, and one active desktop controller have equivalent access. - Controller action and workspace radials are tap-open, explicit-confirm surfaces with at most eight stable sectors per page; release never activates a sector. - Activating a text field with a controller opens the modal QWERTY editor. Its draft preserves the original text, caret, length and multiline constraints; Done returns the draft to the field without submitting its outer action, and Cancel restores the prior value. Scenario installation uses Godot's embedded file dialog so it remains focus-navigable. The Controls page edits a separate binding draft and applies only a reachable, conflict-free result.
- Land maps retain the complete eight-direction movement compass through pointer, keyboard, and keypad. - A pending request suppresses exploration and route mutation. `InteractionPresenter` preserves request ID and exact response payload.
- Positive Classic messages reuse the existing narrative well without a redundant "Classic Textbox" title, formal Continue button, or generic Auto Note/journal helper copy. ## Package media and secrecy

Package media lookup is exact by four-character resource type plus signed ID, so `cicn 128`, `ICON 128`, and `PICT 128` cannot collide. Type case and trailing spaces remain significant. Missing or ambiguous media produces a neutral framed fallback and a developer diagnostic containing the authored key, presentation role, effective package asset ID, hash, and decoder outcome. Presentation never guesses a filename.

Detached views expose only facts needed to draw the current state. In particular, an unidentified item cannot reveal its identified name, definition identity, value, description, curse relationship, or other hidden behavior. Navigation and presentation settings never mutate simulation.
