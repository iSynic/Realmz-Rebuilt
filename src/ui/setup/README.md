# Setup UI

This folder owns the stable application surfaces shown before ordinary exploration: the installed-scenario browser and the retained party setup workspace. Party assembly and the five-step character creator are modes of the same workspace so switching modes preserves the six party slots and current campaign context.

`startup_front_door.tscn` is the lightweight launch-card composition. Its neighboring `front_door_menu.tscn` is the directly editable application identity and four-command entry menu. `StartupFrontDoor` deliberately instantiates that menu only after the launch card's first frame, keeping imported menu media off the critical path. `CampaignLibraryController` binds its lifecycle and binds campaign summaries and package-operation state to `campaign_selection_panel.tscn`. The campaign selector authors its selected-summary, empty, progress, installation, and refresh states and exports `campaign_package_row.tscn` for the variable installed list. `CampaignPartySetupController` mounts that panel beside `party_setup_workspace.tscn`, then delegates variable Character File rows, party slots, and character-draft content to the assembly and creation controllers.

The scenes own panels, headings, scroll regions, alternate states, options, and actions. Controllers may instantiate exported changing records and bind values or signals, but they must not reconstruct stable controls. Startup changes are performance-sensitive because these resources are prepared in the background application graph; use three warmed `tools/startup_probe.gd` samples and the presentation shell fixtures.

Party assembly mounts the lazily loaded `party_assembly_browser.tscn`, whose heading, empty state, and pager remain editable while exported `party_setup_character_row.tscn` instances represent the current vault page. Selecting a party member opens `party_setup_inspection_overlay.tscn`; that overlay owns its Back/header/scroll composition and mounts the same complete character-sheet scene used elsewhere.

Character creation is directly readable as five sibling scenes: `character_creation_identity_step.tscn`, `character_creation_race_caste_step.tscn`, `character_creation_appearance_step.tscn`, `character_creation_review_step.tscn`, and `character_creation_spells_step.tscn`. Together they own every stable preview, selector, detail record, alternate state, and action-adjacent status in the wizard. Appearance instantiates `appearance_thumbnail_row.tscn` for each detached catalog group; Starting Spells instantiates its exported shared spell button and effect preview. The production controller retains only draft coordination, source-backed filtering, and typed intent submission.
