# Faithful scenario records

Providence decodes native files once. Rebuilt consumes their immutable typed representation through its existing catalogs and VM. Preservation does not establish that a record is safe or useful to execute.

Imported package schema v7 retains complete records, empty bodies, fixed slots, invalid references and supplied fragments. The retained source index and content-addressed payloads recover the original bytes. Declared native edits carry exact preimages and effective hashes; approved display projections have separate receipts. A fragment never gains invented completion bytes.

When original source bytes also serve as an operational media payload, both descriptors reference the same exact payload path. Source retention preserves that media encoding choice rather than adding a second copy. Source-only bytes remain losslessly compressed. Save-update accounting records path-only relocations and canonical sorting of the unique source-file index separately; native record order is unchanged. It still verifies every original byte, source identity and other index field.

The typed native catalog distinguishes absent, partial and complete records. Simple encounters retain four native choice slots and four eight-slot result programs. Timers retain all twenty signed words; scheduling still applies the native 151-row scan and zero-day terminator. Shops retain all 1,000 item/quantity positions, including holes and category terminators. AP, XAP, Complex result and Extra Code facts bind compiled instructions, exact owners and the complete program inventory to the effective native bytes at admission. A defined native record missing from compilation is a package defect; reclassifying its caller or adding an unbacked program also rejects.

Player Maps retain all 42 signed words and 256 note bytes per supplied MD2 row. The twenty-slot display catalog includes safe rows without requiring a script reference. Acquisition of a fixed slot precedes optional display, including absent or unusable displays. Scrolling TEXT exits before image calculations, so unused image inputs do not invalidate it. PICT uses its signed level only as marker context. Unsafe image arithmetic omits display; acquisition outside slots 0–19 is skipped without RNG. This is a deliberate safety boundary around unchecked native access, not inferred authored content.

Battle and Monster extents remain addressable in each native monster-set namespace. Inspection does not authorize construction: an impossible footprint, unavailable attack row or unusable battle member cannot create a smaller winning battle or a reward. Fixed-table spans outside a gameplay decoder's representable namespace remain explicitly accounted source spans. They are not padding and do not acquire fabricated typed definitions.

Scenario spell mechanics import independently of their optional name resource. Providence retains all representable complete physical rows and every original overflow or fragment byte. It validates the complete model prefix before projecting the native 105-slot custom bank; extra physical rows remain read-only inspection data. They cannot create additional spell levels or classes. Both early setup and full v7 admission reject operational definitions outside Castle's five seven-by-fifteen banks. Fresh authoring retains those same capacities.

Native startup filenames retain their actual directory-entry spelling, including on Windows. Canonical campaign names remain separate from Data CI's Contact title. Currently unconsumed Contact title, payment and caption slots are retained and individually accounted presentation fields; their absence from a current screen does not make their source bytes disposable.

The original-source catalog includes exact four-byte resource types, including NUL and high-bit bytes, occurrence numbers and signed IDs. Interpreted presentation assets still use their existing resource-key contract. An undecodable fork remains a diagnosed retained source, not an invented empty resource catalog.

Within one native fork, duplicate PICT/cicn/sound keys select the first resource-map occurrence, matching the pinned Castle ResourceDASM reader. Every occurrence remains preserved; a decode failure in the first does not select a later duplicate or authorize an unrelated replacement. Conflicting independently authored asset descriptors retain their explicit ambiguity handling.

Recognized MADG music retains its original bytes and custom-slot descriptor without claiming a general MAD decoder. An exact source hash matching the application's documented original or approved legacy replacement uses that existing application recording. This preserves Trouble's stock `After the Rain` copy without duplicating stock audio or guessing from Custom 2, the title or campaign name. Other unsupported music remains unsupported.

## Signed references and execution

Interpret each operand according to its opcode, field, mode, sentinel and caller before looking up a target. Negative values and zero are not globally invalid. Preserve negative-opcode GOSUB, its opcode-14/23 exceptions, signed battle macros, encounter-local destinations and exact resource keys. The signed-short minimum remains an unmatched raw opcode after checked negation.

For v7, established source absence is handled at the operation boundary:

| Operation | Outcome |
|---|---|
| Optional picture, sound or narration | Omit the absent presentation and continue. Scenario exact keys retain precedence over application fallback. |
| Unavailable mutation target | Leave that target unchanged, keep prior effects and continue. |
| Unavailable program transfer | An empty GOSUB returns; a replacing transfer finishes its frame. A source-backed empty entry completes normally. |
| Interaction requiring unavailable or unsafe data | Cancel the attempt and retain its originating AP unless an earlier instruction already changed it. Do not invent payment, victory, rewards or quest progress. |
| Unknown native opcode | Trace the original instruction and follow Castle fallthrough. |
| Compilation omission, corrupt package, runtime invariant or recognized unimplemented behavior | Reject or fail explicitly. These are not authored absences. |

Quiet compatibility events are maintainer diagnostics, not ordinary narration. Safe continuations remain saveable. They do not clear a fault already recorded by an older run or reconstruct unavailable unsaved state. Undefined native reads receive documented safety corrections, not a claim that Castle produced a particular result. [The fidelity ledger](fidelity-ledger.md) records those distinctions and the source-cell monster-macro handoffs.

Opcode 64 compares signed day/hour thresholds directly, with -1 as the wildcard. Hour 24 is a valid always-qualifying hour threshold; other negative thresholds select their ordinary comparison result. The selected target is transferred literally, including XAP zero. No clock-field range validation or RNG draw is added. Earlier packages retain their prior validation.

The native quest array has 128 signed entries. V7 operations address slots 0 through 127, including signed set/clear operands; legacy packages retain their previous operation limits. Save v5 already represents the sparse signed quest map, so this requires no wire change. An unavailable quest read cancels that attempted test at its boundary rather than choosing a quest outcome. Opcodes 85 and 126 use Castle's signed-short range arithmetic, including inverted endpoints and wrapped widths; `Rand` consumes one draw even for zero or negative widths. Opcode 47 clears quest zero when its operand is zero. Negative battle IDs retain forced bad surprise; opcode 2 ranges over magnitudes and restores the low endpoint's sign, while selective and defeat-hook battles range directly over signed endpoints. Resource IDs, monster-name IDs and map selectors retain their operation-specific meanings. Opcodes 87, 88 and 127 compare signed authored monster-name IDs. Opcode 123 compares the original signed Data MD reference recorded at battle construction or opcode-124 spawn; it does not derive that sign from current allegiance. Held allies and newly summoned actors start with routing identity zero. See FD-SCENARIO-017 for the bounded correction to Castle's unrelated random-weapon initialization side effect.

The bundled refresh retains the previously reviewed movement/collision projection. The receipt-bound Providence projection tool verifies identical native maps, dimensions, tile values and identities, then copies only cell columns 1, 2, 3, 6, 11 and 12 and boat replacement profiles from the exact pinned baseline. Trigger membership, random slots and artwork stay generated from the new native compilation. This separates record preservation from a new travel-rules change.

Land display derives icon identities from the preserved typed native tile, including older immutable packages whose positive CICN overlay alias was absent. It follows `centerpict`'s signed adjustment and bounded marker removal, exact scenario-before-application resource chain and lower-right anchored 64-pixel axes. Acquired land-map crops keep `fastplotmap`'s separate negative adjustment, one-cell icons and base-only positive icon cells. These presentation corrections change neither native bytes, movement/collision, package bindings nor save formats; existing adventures require no Update Save for them.

Battle construction reads native y-then-x rows only until the 100-monster capacity is filled, including living held allies. Unconsumed trailing cells remain catalog data, not actor dependencies. It skips each zero-HD native row independently. A battle with no constructed rows cancels its attempted interaction before victory or rewards. Unsafe footprints, attack extents, random-weapon tables and unavailable carried-item dependencies stay in the catalog; their selected construction is bounded before an actor can enter saved state. A dependency supplied by native source but missing from the compiled catalog remains a package defect. V7 unsafe summon selections keep the existing selection draw and ordinary resource/action costs without rerolling or inserting an actor. Polymorph validates all six retained carried slots and does not construct its unused random weapon. Unsafe polymorph selections leave the target unchanged after the selection draw; later group recipients still resolve. Negative spell points are signed state, not a reason to reject a record.

V7 definitions retain signed nonzero death-macro handoffs. Empty authored targets still pass through the ordinary direct or queued completion owner, preserving their different allegiance-reset semantics. Earlier packages retain their positive-only interpretation. These construction boundaries and the existing table-10 random-weapon alias are documented safety corrections in FD-SCENARIO-018; signed battle/range semantics are source-backed corrections in FD-SCENARIO-019.

## Saves and updates

Schema v3–v6 packages retain their existing record meanings. The save envelope remains v5 and Character Files remain v2. V7 battles add one optional signed `classicRouteId` field to each monster state; legacy states omit it and retain their prior interpretation. Existing adventures stay bound to their retained package until the player explicitly selects **Update Save**.

Each allowed old-to-v7 pair pins both archives, the application identity and the complete file delta. Translation maps recorded compact Simple positions, shop positions and timer cursors to native positions; it never replays scripts or changes recorded outcomes. A detached restore and complete serialized readback must succeed before a separately named copy is offered. Old-package mid-battle states cannot establish the original signed routing identities after charm or transformation and must finish that battle before updating. Ambiguous mappings and unsupported nested macro waits reject with guidance to finish the interaction against the original package. Originals, backups, packages, RNG, the active adventure and Quick Save target remain intact.

Random-region overrides and VM/session continuation identities translate by exact native map and slot. A pending random scan is eligible only when its complete region order, geometry and cell membership remain equivalent; newly restored regions can make that pending state ineligible. Finish it against the retained package first. Age-held clock continuations receive the same timer-cursor check.

Historical media, shop, marker, payment, program-restoration and compression receipts remain immutable. Supporting an earlier revision requires verifying its original transition before the independently pinned v7 transition. There is no general hash rebinding or automatic migration, and no character repair is part of this change.

The complete-record receipt names thirteen immediate v6 pairs and forty already-supported historical predecessors. Older media/shop transitions whose original archives are unavailable are not silently broadened into direct v7 pairs. Their original policies and receipts remain retained. The authoritative maintainer source is `complete-records.json`; the game reads only its hash-pinned zlib copy, verifies exact decompressed length and source hash, then caches the parsed receipt. Unavailable or mismatched evidence disables the update.

## Verification

`tools/verify_classic_records.py` independently decodes retained source framing, full program bodies, signed Extra Codes, Simple choices, timer words, shop positions, random-region slots and exact resource inventories. It compares original and effective source spans and rejects missing or changed facts. Correction receipts must identify exact source and package values; unused exceptions fail verification. Its corruption probes run with `--self-test`; package checks take explicit `--package` paths and optional exact correction/source-context receipts.

The numeric, world and support projection helpers additionally compare complete operational rule fields, Monster/Battle namespaces, messages and option captions, Layout and raw maps, MD2 displays and exact resource keys, startup/restrictions/contact/hooks, special-cell solidity and all supplied custom terrain sets. Native editor text preserves the supplied Pascal payload; compiled captions apply their separately defined display boundary. Native Race/Caste fact arrays retain all supplied complete rows independently of selection. Fixed thirty-slot commitments bind each effective full wire row, with null only for a source-proven partial or absent selected-native row. Short supplied families never inherit stock replacements; absent families retain independent application fallback. Early setup checks the same bounded source and rule commitments as full preparation. Stock item placeholders at IDs 800 and above cannot fill absent v7 scenario NI rows or transfer metadata.

Native v7 character creation preserves source byte/short assignment boundaries, sequential pins, signed dice and unconditional age draws. A minimum age group outside the native five-row table rejects only the attempted creation. Creation publication requires exact codec readback after starting equipment; rejected setup restores the prior draft, pending interaction, instance allocation and full RNG checkpoint. Advancement uses detached character/RNG candidates. An unrepresentable result leaves those untouched; opcode 102 retains prior XP, while rewards retain earned XP and earlier committed effects and continue with other characters. These unsafe-operation boundaries are deliberate safety corrections, not numerical-quality filters on definitions or claims about unchecked Castle memory. See FD-SCENARIO-021.

Local converter regression covers all forty titles in the private `D:/Scenarios` corpus, alongside the pinned corrected bundled sources and differing private revisions. Previous import history, unfinished authoring and source defects do not reduce that denominator. Original source identities, conversion, byte-exact no-edit export, package admission and gameplay coverage are reported separately. Private source folders and generated packages are external verification inputs, not release assets or prerequisites for public CI.

Inventory accounting, package admission, direct VM invocation, visible controls and ordinary gameplay are separate evidence. Neither a compiler stamp nor successful startup establishes campaign parity. Release checks must bind reviewed inventories to the tracked archive hashes and actual exported PCK contents.

The maintainer workflow is:

1. Build the clean, pinned Providence source update and generate packages in two fresh directories. Use its archive writer and inspector for every reviewed projection; never rewrite an accepted candidate ZIP in another tool.
2. Run `tools/prepare_complete_record_updates.py` with explicit `--before-dir`, `--after-dir`, `--application-package` and fresh `--output` paths. Review every reported document and asset delta, not just added IDs.
3. Run `tools/compose_complete_record_history.py` with those explicit baseline/candidate/review paths and a hash-verified original historical archive index. It maps typed positions without inferring missing old native annexes. Retain its exact historical content/world/manifest fixture for independent map verification.
4. Generate byte-exact baseline recipes with `tools/complete_records_history.py generate`, reconstruct them into a fresh directory, and verify the original historical policies there. Update package/provenance/inventory and receipt pins together; generate the zlib receipt at level 9.
5. Run `python tools/verify_complete_records.py`. This rechecks original/effective native facts, manifest/content identities, all declared corrections, the historical endpoints and all 53 explicit state mappings. `tools/verify_bundled_scenarios.ps1` selects this gate for v7 bundles.
6. Run `tools/complete_record_save_update_probe.gd` against an explicit external route manifest and fresh scratch storage. The shared historical probe supplies full-envelope, backup, collision, failed-publication, readback and live-session preservation checks. Exercise changed pending semantics separately.
7. Regenerate setup caches, run the aggregate, and inspect the actual Windows PCK with `tools/verify_release_artifact.ps1`. The plain receipt, baseline catalog and maintainer inventory must be absent; the compressed receipt and thirteen exact archives must be present.

`tools/fixtures/complete-records-history` contains maintainer-only public-campaign evidence. None of its reconstructed archives or historical state documents belongs in the runtime PCK. Two independent reviews apply to the same final code revision, package identities and evidence; scores do not establish full campaign playthrough parity.

Clock/combat execution introduced save v6 (the writer is now v7 under ADR 0026); this does not change schema v7, compiler or archive identities. See [the execution and evidence contract](clock-combat-compatibility.md).
