# Scenario execution ownership and transitions

This is the execution contract accepted in ADR 0029. `scenario-vm-evidence.md` records its source, native, synthetic, historical-save and authored-caller verification boundaries; the contract does not claim whole-VM Castle parity or campaign certification.

Source pin: Castle `491816ad60037394f92c428e99c004494d3c28b3`.

## Ownership

| State | Owner and source constraint |
| --- | --- |
| Selected placed AP | Shared native state (`doornum`); loading XAP code and pulling GOSUB do not restore it. |
| Active record and destination header | Shared native state (`infodoor`); keep their identities explicit. `loaddoor2` replaces the code record while retaining its incoming map, coordinate, percent and door identity (`flashrange-loaddoor.c:43-62`). |
| Manual GOSUB stack and retained flag | Shared native state. Entries contain the saved active record and native slot (`stack.c`). Native `newland` entry resets the stack; opcode sign updates `gosub` under the exact rules below. |
| Loaded Simple/Complex records | Shared structures with captured code identities and loaded marks, separate from stored structures/marks. Nine shared text-source references retain independent text ownership. A saved structure base may differ from its destination. Missing historical code/text stays unavailable. |
| Encounter repetition | Shared native `encountflag`/`enctry`, separate from the invocation-local `encountid`, `encid` and `enc2id`. Result copies replace active code; returning from mode -1 skips the ordinary repetition/clear epilogue. |
| Invocation position and guards | Typed invocation-local record: compiled cursor, native slot, mode, phase, secondary-header and no-second-door guards, saved encounter exit, one native save destination shared by Simple/Complex entry, and caller-specific return values. |
| Safe Action values | Dedicated Safe execution record: declared parameters, locals, iterator state and return destination. No Safe local or iterator fields are imposed on Classic state. |
| Incomplete gameplay work | Typed operation record with a fixed resume phase and explicit caller. It carries detached gameplay values and stable identities, never a live VM or a VM snapshot. |

`newland.c:26-68` resets `stackindex`, `memoryspell` and `collideflag`; mode -1 skips the ordinary encounter initialization. Other invocations reset encounter repetition before mode-specific entry. A caller's saved code/header copies are separate from these shared resets.

## Classic transitions

- At a native instruction, negative raw codes except -14 and -23 set `gosub = true`. Other codes clear it only when the manual stack is empty (`newland.c:97-106`). A positive branch inside a nonempty stack can therefore retain GOSUB intent.
- A branch pushes only at a source `pushonstack` site. The source sites belong to opcodes 3, 21, 31, 40, 46, 55, 56, 64, 67, 72, 75, 76, 77, 78, 81, 85, 86 and 87. Branch selection and sentinels still decide whether a particular site executes. In particular, opcode 67's successful encounter target -1 pushes before continuing without a transfer.
- Opcode 25 explicitly clears retained GOSUB, manual returns and encounter state. FD-SCENARIO-028 preserves immediate timeline completion as a deliberate correction; Castle instead continues the following slot.
- Opcodes 8 and 39 replace execution without a generic push. The shared `forcebranch` path used by 33, 38, 42, 58 and 59 does not push; opcode 46 performs its own push before entering that path. Preserve documented fidelity corrections independently of this source table.
- Opcode 111 pulls one saved record and resumes its following native slot. An empty stack falls through. Opcode 112 discards one entry without changing the active record (`newland.c:108-121`, `stack.c`). Reaching record end never substitutes for opcode 111.
- Simple/Complex entry loads the encounter and repetition count. Selection copies its result codes into the active record and restarts. Direct opcode 4/5 entry does not manufacture a GOSUB push; a branching opcode may already have pushed at its own source site (`newland.c:1573-1705`).
- At natural result completion, mode -1 returns to its macro caller before the ordinary epilogue. An explicit `keepcodes` jump enters that epilogue even in mode -1. `END_RECORD` selects the natural path without inferred flag changes; `KEEP_CODES` explicitly clears the flag for opcode 24 and forcebranch mode three and retains the flag for 42/58/59 mode two and opcode 75's failed spell-point mode one; repetition uses the source postdecrement and the selected record, including the final Complex fallback-to-timeout rule (`newland.c:1692-1693,2810-2835,3725-3739`). A native Simple first-choice result -4 bypasses the dialog and copies result four (`newland.c:1608-1611`). Cancellation returns from the entire invocation.
- Encounter selection commits its native flag/identity/attempt separately from code copying. `COPY_RECORD` selects only the captured code and native slot. Opcode 46 commits its source push before choosing a transfer, dropout or unmatched-destination continuation; forcebranch itself never pushes.
- Opcode 41 changes only stored marks; 44 changes only the loaded Complex result, including a fresh zero buffer. Opcode 7 loads/replaces/saves a structure without loading text or changing the invocation's save destination. Opcode 35 and cancellation save the current structure to that explicit destination while preserving destination text. Repetition and forced reopen never reload the structure (`newland.c:1582-1699,1740-1780,2594-2599,2795-2807,2838-2842`; `encounters.c:269-345`).
- Opcode 34 restores the explicitly saved encounter-exit record and follows its issuing native slot. Opcode 35 reopens Simple choices without the ordinary repetition decrement or opening sound (`newland.c:2583-2595`). Neither discovers its owner by searching frames.
- Native slot seven, GOSUB return slots, encounter result entry slots and timer-return slots use one compiled-position mapper. It preserves existing ordered Safe calls; native slots are not assumed to be compiled array indices.

Default removal occurs before repetition/header completion only for a declared placed owner reaching natural completion with no active encounter. It changes the shared selected AP, independently of the issuing owner. Keep Codes skips that default; failed rechecks return before repetition. Placed headers use the same runner-owned completion as mode-one work, preserving manual returns and the single secondary-header guard. Backout and opcode-70 suppression remain typed, invocation-owned facts.

Immediate native returns skip both encounter repetition and header completion; their return values are independent of committed operation values. Source owners choose each exit explicitly, without VM opcode inference. Historical age exits normalize at the codec boundary into explicit end/reset transitions. Schema-5 operations reject the historical tags; the production runner does not dispatch them.

Shared header mutation and native guards are committed typed operation facts. Opcode 20 rechecks immediately; opcode 37 returns without replacing the shared header; opcode 45 suppresses its later recheck. Opcode 61 changes the header coordinate while retaining its map identity, and 70 restores its destination explicitly. Fresh entry after an idle restore retains the newly selected caller header. Manual returns distinguish absent, known and historically unavailable destinations.

## Native calls and gameplay operations

Each call records its source entry mode, stable entry program and exact return operation. The invocation keeps that entry identity when overrides, transfers or nested calls replace its current code; restore binds it to the explicit call rather than requiring the current position to equal the initial target. A death macro's code/Extra Code restoration (`killbody.c:107-151`), battle caller restoration, timer-induced replacement and application-hook return must not be generalized into one snapshot restore. Revival and terminal combat cleanup remain rules-owned and happen once after the macro's return phase. Timer child calls retain an age/scan cursor without another VM. Entry applies mode-one resets; return keeps the code and GOSUB stack left by the child and resumes the original following native slot. A controlled synthetic timer fixture observes opcode 111 consuming a timer-left GOSUB entry after return. Clock, combat and spell outcomes now carry required age acknowledgements directly; their saved age owners retain the batch and exact return phase. No event-history adapter reconstructs that work. Historical battle/death and opcode-125 macro wrappers now convert into explicit callers, including direct-session owners. Legacy families convert at their strict codec boundary; missing historical values remain explicitly unavailable.

Opcode 48 preserves only `encountflag` (`newland.c:3078-3134`), unlike the code copies in opcodes 2/56/107. Its operation record retains that flag and maps the caller's following native slot against the current code after return. Native invocation facts remain local even when a child leaves different shared code. Shared state separately retains the signed-short repeat counter, macro-monster index and battle-macro flag. Immediate death return resets the index; a queued call with index zero leaves it unchanged (`killbody.c:107-151`). Queued calls capture the original program, signed allegiance, native index/name and position at the lethal effect (`killbody.c:88-96`). Later definition, allegiance or position changes cannot replace those facts. Opcodes 119/123/124 select shared or local subject facts at their individual source sites. Required death work travels in typed combat outcomes; feedback events never schedule it.

The controlled observations in `tests/fixtures/oracle/classic-shared-execution-state.json` confirm that combat clears the encounter flag without clearing its counter, a round macro can replace both, and macro return preserves that replacement. A second case checks the actual saved native bytes: opcode 35 writes the currently loaded 106-byte Simple structure to the caller's local save identity while preserving that destination's text. `encounters.c:269-345` does not reload the record in mode false. The implementation now retains loaded-buffer/local-save ownership explicitly. Remaining legacy families and nested queue-drain acceptance remain work. The fixtures use prepared native entry and actual combat controls; they do not establish mirrored combat RNG or campaign parity.

One local counter bounds each uninterrupted runner entry, including all child invocations and their returns. It retains the 65,536-step safeguard and resets after an external response or handoff, without a runtime weak reference or saved counter.

The runner retains callers below their work. An operation yields a request, calls another execution record, completes, rejects or fails. Its next phase is independent of the events emitted by earlier phases. Age acknowledgements, timers and Party Death may interrupt the operation while preserving that phase. Direct-session combat enters the same macro lifecycle with its own explicit return kind. Safe calls inherit a saved native-invocation owner from their direct caller. HALT ends that invocation and continues its explicit header/child return; it cannot erase an enclosing battle or timer caller. Standalone Safe roots retain their own terminal outcome.

Application hooks now retain callers in the same runner. The saved session body names the application operation; its child call retains the explicit native code, manual returns and control required by FD-SCENARIO-026. The live destination header is excluded from that copy. Opcode 119 returns native -1 immediately, separately publishing typed revival; it cannot run an encounter/header epilogue or schedule revival from event history. Historical timer children and clock-wrapped Party Death callers now flatten at detached restore before application-owner validation. Their declared scan rows and return slots bind to exact content. A historical post-move depth-one arrival maps to the named invocation's header-suppression guard; its remaining session field is admission provenance. Other legacy caller families remain acceptance work.

Terminal battle operations carry `BattleReturnResult` beside committed feedback, and direct-session coordination consumes that typed return. Opcode 122 selects its native exit from the closed fumble outcome. Movement-attempt searches return their fresh discovery fact, matching `buttonchoice.c:229-231`; earlier events cannot request another native entry. Generic session event-history query helpers are removed.

## Save boundary and proof

The twenty-two synthetic cases in `tests/fixtures/oracle/classic-execution-transitions.json` have pinned `castle-runtime` observations: fourteen use direct mode-minus-one entry and eight use prepared ordinary movement. Their per-case checkpoints distinguish instruction draws from the four movement/admission draws. The runner compares native opcode/operand/stack traces, selected AP chances and instruction RNG, then compares uninterrupted execution with 107 real JSON restoration boundaries. The failed-recheck case explicitly maps native coordinate 8,20 onto the existing synthetic marker at 1,0. Authored AP/header graphs and campaigns require separate acceptance. The slot-seven fixture observes an unchecked slot-eight fetch; FD-SCENARIO-027 defines the bounded Rebuilt behavior.

A separate prepared scenario-macro probe traverses combat, round-macro acknowledgement, combat return, reward completion and an opcode-35 reopened result across five JSON save/read/full-session restores. Its exact state, events and RNG draw order match uninterrupted execution; a debug terminal command bounds the battle. It proves the stored destination retains its text while taking the child structure. It is separate from the native structure-byte fixture and from ordinary campaign play.

VM schema 5 encodes the ordered records, explicit ownership, exact pending interaction and resume phase, required shared Classic state, request counters and type-tagged Safe values. Codecs reject unknown fields, tags, phases, identities, contradictory ownership and invalid bounds before restore assignment. Legacy v5-v8 continuations are converted at that boundary, including nested timer, battle/death macro and suspended application owners. Missing native history is never synthesized. An old active encounter owner provides its explicit lookup identity and attempt count; the content-bound decoder combines those recorded facts with its package maximum and saved marks/redirects. It does not infer unrelated buffers or consume an instruction to reconstruct them. The saved shared header is bound before runner assignment.

Tests must distinguish source-proven control flow from controlled native execution. The replacement matrix covers signed/positive nesting, retained GOSUB, empty-stack 111, 112, sparse slot seven, program overrides, result copies, repetition, cancellation, record/header ownership and each nested workflow. Every admitted yield compares real JSON restore with uninterrupted state, request, effects and RNG state/draw order. Saving, loading and projection consume no gameplay draws. Existing package identities, explicit Update Save eligibility and fidelity corrections remain fixed.
