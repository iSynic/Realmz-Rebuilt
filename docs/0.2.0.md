# Realmz Rebuilt 0.2.0

Realmz Rebuilt 0.2.0 brings the new scenario runner out of testing. Encounters, scripted battles, death and revival, and timed events now run on one engine, and you can save and restore in the middle of them. This release also includes every fix from the three release candidates, better Reveal Friends lines, and two new optional combat displays.

[Downloads for Windows, Linux, and macOS](https://github.com/iSynic/Realmz-Rebuilt/releases). Extract the complete archive and keep its importer and music-importer folders with the game. This release contains desktop builds only; no Android APK is included.

## New since Beta 27

- **One scenario runner.** Branches, encounters, battle and death macros, timers, and application scripts share one execution model, following the Realmz Castle codebase. This replaces the overlapping paths behind the recurring continuation bugs. Suspended scripts keep their exact pending prompt and next step across save and restore, without replaying effects or rerolling decisions.
- **Moving into an enemy attacks in missile mode** ([#27](https://github.com/iSynic/Realmz-Rebuilt/issues/27)). A numpad or click move into an adjacent enemy attacks with your melee weapon, or unarmed, even while you're set to missile. Your next Fire still uses the missile.
- **Revived scenario allies sit out the rest of the battle** ([#26](https://github.com/iSynic/Realmz-Rebuilt/issues/26)). NPCs that scenarios keep alive with code 119, such as Jhalor Fireblade and Naryl Dragonstone in Trouble in the Sword Lands, now leave the battlefield when killed and rejoin your party with 1 Stamina afterward, instead of getting straight back up.
- **Reveal Friends reaches off-screen combatants** ([#28](https://github.com/iSynic/Realmz-Rebuilt/issues/28)). Lines to friends and enemies outside the battle view now run to the edge of the view in their direction, as in Castle, instead of being left out.
- **Optional combat hash marks.** Turn on **Settings > Display > World View > Use combat hash marks** to see short green, red, or blue marks at the battlefield edge pointing toward off-screen friends, enemies, and helpless combatants on your characters' turns. This is Castle's own optional preference, and it's off by default.
- **Optional disease damage icon** ([#29](https://github.com/iSynic/Realmz-Rebuilt/issues/29)). Classic Realmz shows only text when disease deals damage each round, while poison also shows its green icon. We confirmed that by playing the same battle in Castle and Rebuilt. If you'd like the icon for disease too, turn on **Settings > Adventure Rules > Show icon for disease damage**. It's off by default and changes only what you see.
- **Smoother combat account.** Account updates are combined within a frame, which reduces handoff work without changing combat decisions, event order, or random rolls.

## Saves and returning to Beta 27

**0.2.0 writes save v9 and reads v5–v9. Beta 27 cannot read v9.** Loading an older save doesn't rewrite it; saving in 0.2.0 writes the new format. If you want to keep the option of going back to Beta 27, keep an untouched v8-or-earlier save. Beta 27 stays available on the releases page.

All versions use the same local data folder, so extracting another copy of the game doesn't give it separate saves or Character Files. Back up saves and characters you care about before upgrading.

A battle saved while a revived ally is sitting out records that fact. Release Candidates 1 and 2 refuse that save instead of misreading it. Character Files v2, the application library, the bundled scenario archives and the package formats are unchanged, so no reimport or Update Save step is needed. Save v1–v4 and Character Files v1 remain unsupported.

## Reporting problems

Use the [bug report form](https://github.com/iSynic/Realmz-Rebuilt/issues/new?template=beta_bug.yml). Include the version, operating system, scenario, exact steps, and an original save from before the problem when possible. Check attachments for private information before sharing them.

## Known limitations

The intermittent combat spellbook-input issue remains unresolved: Power Level, Choose Targets, and Abort can sometimes stop responding while Back to battle still works. Returning to battle and reopening Spells may help.

The optional modular HUD remains a work in progress; the fixed HUD is still the default. Verification covers the documented execution, restoration, legacy-save, campaign-caller and combat cases. It does not certify every route through every campaign.
