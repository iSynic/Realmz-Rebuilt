# Shell and routing

`game_shell.tscn` is the recognizable overworld HUD: menu, play stage, roster, narrative and status well, command decks, effects, and overlay hosts. Exploration and combat are modes of that shell. Workspaces replace the primary workspace region and return through `ScreenNavigator` history.

Routes are declared by typed route resources, not free-form dictionaries or one-node marker scenes. Workspace scene paths remain selectable in the Inspector but are loaded only when opened, so building menus does not eagerly load every major workspace; Godot's ordinary resource cache handles later reuse. The navigator owns mounting and history, while `WorkspaceFocusController` preserves focus identity and scroll position across a route rebind. Setup data goes directly to `CampaignPartySetupController`; detached workspace data goes directly to `ScreenContentPresenter`. `ScreenNavigator` does not mirror either controller's public API. Each scene controller owns binding and local presentation state. `test_classic_ui_shell.gd` protects shell composition and `test_classic_ui_system.gd` protects navigation and responsive behavior.

`GameShell` binds the complete scene and coordinates its collaborators. `GameShellLayoutController` resizes the authored controls using the calculations in `GameShellLayoutPolicy`; `GameShellStatusController` binds narration, status, location facts, and the transient save/journal indicators; `GameShellPartyEffectsPresenter` animates the eight authored effect slots; `GameShellMenuController` owns menu definitions and dispatch; `GameShellAvailability` owns player-facing reasons for disabled routes and application actions; `GameShellCommandController` owns the dynamic command records and selected Fast Spell lookup; `GameShellPicturePresenter` decodes and presents scenario pictures in the authored stage; and `GameShellRoutePolicy` chooses only automatic workflow transitions from detached state. A shell edit should begin in `game_shell.tscn`, then continue in only the collaborator that owns the affected behavior.

`PresentationCoordinator` applies committed detached views, interactions, spatial visibility, and combat playback. `PresentationMediaController` separately composes application, character-library, and active-scenario media, installs that catalog on its consumers, and selects route-aware music. The application constructs both owners explicitly; code that changes a package or needs an effective media lookup addresses the media controller directly rather than adding a forwarding method to the view coordinator.

Application hosts address these public collaborators directly. Save and lifecycle code updates `ScreenContentPresenter`, Character Files setup updates `CampaignPartySetupController`, interaction presentation binds the persistent roster, and player-facing messages enter `GameShellStatusController`. `GameShell` does not mirror those APIs.

The shell's persistent Party rail begins at `src/ui/shell/classic_party_roster.tscn`. Its member record, empty position, selection number, current-character marker, combat Auto toggle, and pointer-following selection count are editor-authored. `ClassicPartyRoster` binds detached `CharacterView` records, preserves matching rows during incremental exploration updates, and performs only source-backed portrait compositing. Its exported member and empty-row scenes are the only variable roster records.
