# World and exploration

`MapTopology` is the sole immutable map truth. `WorldState` is the small save aggregate around three direct collaborators: `WorldTopologyState` owns terrain, boats, doors, secrets, darkness, and landlook changes; `WorldTriggerState` owns Action Point availability and effective random regions; and `WorldExplorationState` owns visited/seen cells, acquired maps, and player location notes. Their serializers preserve the established flat `worldOverlays` save shape. `ClassicLandTileRules` decodes signed Castle tile identities without retaining playthrough state. `RealmzClock` owns the saved minute count and its day/hour/minute projection, while `ClockRules` owns fatigue, hourly condition/spell recovery, aging, and half-day recovery. The matching transaction owners are neighbors under `src/playthrough/world`: `ExplorationMovementWorkflow` for travel, heading, fatigue, and boats; `ExplorationSearchWorkflow` for Search and secret checks; `ExplorationTimeWorkflow` for Camp, Rest, and Heal; `ExplorationContinuationWorkflow` for saveable post-clock/post-move state; and `LocationNoteWorkflow` for player notes.

Input begins with `ExplorationIntents`, whose factories distinguish ordinary movement, overhead dungeon movement, turns, Search, camp/rest/heal, contextual encounters, Torch, and location notes. `ExplorationIntentPayloads` carries only the direction, heading-alignment, turn, or note value; legality remains in the workflow and rules.

When exploration yields for clock processing, an AP, a random region, or a boat choice, resume state is created by `ExplorationContinuations` and carried by `ExplorationContinuationBody` or `BoatContinuationBody`. The strict central codec preserves those exact save fields without making exploration coordination depend on a generic protocol catalog.

`SessionExplorationCoordinator` reads post-move work as preparation, completed-trigger resumption, next-trigger execution, and random-region continuation. Contextual Encounter separately selects its source-ordered random door or default program before starting the VM. Random-region processing names its chance check, random-door program, destination recheck, and surprise/battle choice; these phases retain the same serialized continuation, event order, and RNG tags.

Both 2D and 3D presentation consume the same detached `MapView`; neither owns collision, LOS, heading, or discovery rules. `SessionMapViewBuilder` names visible-cell selection, viewport bounds, cached or patched window projection, complete-window construction, and movement-option projection while retaining the same bounded caches. Start topology changes in `test_map_topology.gd`, clock/fatigue changes in `test_realmz_rules.gd`, and public journeys in `test_exploration_session.gd` or `test_scroll_camp_workflow.gd`. Use the movement and dungeon-transition probes whenever projection or spatial presentation changes.
