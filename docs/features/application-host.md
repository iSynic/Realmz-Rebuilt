# Application host

`RealmzApplication` is the visible composition root. It constructs dependencies, owns the replaceable session controller, translates host input, and sends detached state to presentation. `ApplicationLifecycleHost` owns quit and End Adventure state, `ApplicationCharacterFilesHost` owns the application library, vault, and standalone creator, `ApplicationAdventureStorageHost` owns adventure save/load/preview operations, and `ApplicationSpatialLayout` aligns the algorithmic map/battlefield/dungeon presenters with the authored shell stage. `StartupFrontDoor` owns the first frame and background construction; none contains game rules.

Follow an input from `ApplicationInputRouter` to a typed session command, and a committed step back through the presentation coordinator. Keep dependency construction explicit and keep campaign loading cancellable. Startup-sensitive changes require three warmed `startup_probe.gd` samples and the ordinary front-door test path.

`RealmzApplication._ready()` reads as five named phases: dependency construction, debug/movement binding, combat/interaction binding, shell/settings binding, and final startup. Add a dependency or signal to the phase that owns it; do not rebuild one long initialization procedure or hide the graph in an untyped service locator.

For lifecycle behavior, begin with `application_lifecycle_host.gd` and the pure option/decision policy in `application_lifecycle.gd`. For adventure persistence, begin with `application_adventure_storage_host.gd`, then descend to `SaveHostController` and the storage repository. For reusable characters, begin with `application_character_files_host.gd`, then descend to the repository-facing controllers under `src/app/controllers`. For responsive stage placement, begin with `application_spatial_layout.gd`; map and battlefield geometry remain in their algorithmic presenters. The owning characterization is `tests/presentation/test_classic_ui_system.gd`, with repository and round-trip coverage in the save and session-persistence suites.

The lightweight entry composition is `src/ui/startup_front_door.tscn`; after its launch card draws, it instantiates the directly editable `src/ui/setup/front_door_menu.tscn`. Keeping the menu scene outside the launch scene prevents its imported media from delaying the first frame. The same menu scene is mounted under the loaded shell when needed. `CampaignLibraryController` binds readiness, video and soundtrack lifecycle, and host signals without constructing controls. `src/ui/setup/campaign_selection_panel.tscn` owns its selected scenario, empty library, package progress, install, and refresh states; only its exported campaign row scene repeats for detached installed packages.
