# Session transactions

`GameSession` is the public adventure boundary: start, restore, submit an intent, respond to an interaction, inspect a detached view, snapshot, and close. It owns rollback, revision changes, request identity, and exact-once commit. Workflows receive an operation-scoped context containing the active content, state, RNG, VM, continuations, and revision services.

`SessionIntentCoordinator` is the command directory immediately behind that boundary. It groups exploration, magic/combat, party, and inventory/service intents, then calls the owning workflow without copying session state. Coordinators construct outcomes directly through `SessionCoordinatorResult`, which distinguishes a pre-transaction rejection that keeps the current revision from a committed failure that advances the revision with its ordered events. `SessionContext` owns new-session initialization, accepted restore assignment, scenario reset, teardown, detached snapshot construction, and shared live collaborators; it does not proxy the result vocabulary.

`PlayerIntent` is the stable command-kind registry and typed envelope, not a catalog of every command constructor. `ExplorationIntents`, `InventoryIntents`, `MagicIntents`, `CombatIntents`, `PartyIntents`, and `EconomyIntents` are discoverable in the `intents` folder beside their owning `src/playthrough` feature. Their payload families name the values consumed by the corresponding workflow, while the small common protocol and `PlayerIntentRegistry` live under `src/playthrough/session/intents` and only reject a payload paired with the wrong stable kind. Add a command to its feature entry point rather than adding another forwarding method to `PlayerIntent`.

`InteractionRequest` is the small registry and wire envelope for pending player decisions. Feature-owned bodies live beside their character, combat, economy, or scenario game model; neutral dialog and selection bodies plus strict request/value decoders live under `src/game/shared/interactions`. Each decoder preserves the established serialized kind, fields, and optional-field rules. Add a new request by defining its body beside the owning game feature, registering its kind and decoder dispatch centrally, then handling it in the owning playthrough workflow and UI binder. Do not grow another feature codec or nested protocol catalog inside `InteractionRequest`.

`SessionContinuation` is likewise only the stable saved envelope for an interrupted transaction. The envelope, body protocol, and strict codec live beside the session transaction under `src/playthrough/session`. World, character, scenario, inventory, magic, economy, and combat code create continuations through the matching factory in their own feature folder; each payload names only the fact required to resume. `SessionContinuationCodec` alone admits their dictionary representation and rejects unknown fields, invalid resume combinations, or a payload paired with the wrong stable kind.

Restore first builds a detached candidate, then `SessionRestoreValidator` validates each continuation against current immutable content, restored state, and the exact reconstructed interaction. Targeted field magic is divided into scroll-discard confirmation, item selection, learned-spell selection, and scroll selection so maintainers can follow each eligibility and request-identity check without changing the shared save payload.

`SessionResponsesCoordinator` is the corresponding response directory. Its top-level match routes every typed continuation to the owning response operation; the unmatched branch is explicitly the random-surprise workflow rather than hidden below the general dispatcher. Multi-stage pooled-wealth departure names its Warning, Distribution, Pool, Share, Swap, and leave-behind phases, while the saved continuation retains the exact direction and stage.

Detached read models begin in `SessionViewProjector`. Its complete path names party, combat, campaign, setup, collection, and action phases; its incremental path retains the prior immutable domains and updates only movement-owned facts. `SessionOrdinaryProjectionPolicy` is the conservative event-sequence gate for that reuse, while `SessionActionViewProjector` groups exploration, magic, setup, inventory/service, combat-movement, learned-spell, scroll, and Fast Spell availability. These projectors are read-only and disposable: they cannot create gameplay truth or broaden the commands admitted by the owning rules.

No UI, repository, Node, or wall-clock dependency enters this layer. New gameplay routes should add or reuse a typed intent and an owning feature workflow instead of exposing coordinator helpers. `test_game_session.gd` protects the command API, `test_scenario_vm.gd` protects the continuation wire denominator, and `test_session_persistence.gd` protects the complete saveable aggregate.
